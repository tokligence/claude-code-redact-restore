# Changelog

All notable changes to redmem will be documented in this file.

## [Unreleased]

### Added
- **deploy_config_guard** (`hooks/deploy_config_guard.py`): always-on `PreToolUse(Edit|Write|MultiEdit|NotebookEdit)` **ask** before editing a file the deploy pipeline consumes — Dockerfiles, compose files, `.github/workflows/*`, frontend build configs, `Cargo.toml`, packaging manifests, platform manifests, k8s/helm files. Catches a failure with a specific shape: an agent needs a dev server or test run to work, something in the build config is in the way, it edits the config, the task now succeeds, the agent reports success honestly, and the edit rides along in the diff to production. Observed instance: an agent deleted `output: 'standalone'` from `next.config.js` so a local dev server would behave, three lines above the production Dockerfile's `COPY .next/standalone ./`. `ask` rather than `deny`, because people legitimately edit these files and a guard that is wrong most of the time gets muted permanently. Deliberately not matched: lockfiles (a stale lock fails loudly at install), `.env*` (the shield's job), and test configs (they break tests, which is visible). Escape hatch `REDMEM_ALLOW_DEPLOY_CONFIG=1`. Fail-open.
  - 64 tests: 56 on the classifier (`test_deploy_config_guard.py`) — the negative cases are the real surface, and one of them caught `Dockerfile[^/]*$` matching `Dockerfile-explained.md` — plus 8 end-to-end through the real dispatcher process (`test_deploy_config_guard_e2e.py`). The E2E layer exists because the unit suite passes whether or not the function is ever *called*, and it was not fully: the guard accepted MultiEdit and NotebookEdit while `install.sh`'s matcher routed neither, so those branches were dead in every real installation. Matcher widened, and the two are now pinned to each other by a test that fails if either moves.
- **git_guard** (`hooks/git_guard.py`): always-on `PreToolUse(Bash)` deny for `git add -A` / `git add --all` / `git add .` (incl. combined flags `-Av` / `-vA`). Closes the gap left by `settings.json` permission rules, which only see literal command prefixes and miss chained Bash like `cd repo && git add -A`. The regex scans the whole command, distinguishes `.` (standalone arg) from `./path` (excluded), and never matches `git add -u` (the safe tracked-only alternative). Escape hatch via `REDMEM_ALLOW_GIT_ADD_ALL=1`. Fail-open. Wired through the dispatcher and also installable as a direct hook for users who want the protection without swapping the rest of redmem.
  - 55 tests (`test_git_guard.py`): 23 parameterised must-deny cases (incl. combined flags + chains + subshells), 19 must-pass safe cases (explicit paths, `-u`, `-p`, dot-slash, unrelated commands), opt-out env behaviour, malformed-input fail-open, and standalone CLI smoke tests.
- **Post-compact tools cheatsheet** (`hooks/cheatsheet.py`): re-injects a concise capability summary into Claude's context on the first `UserPromptSubmit` after each auto-compact, so it remembers `redmem-original`, the autopilot bash-guard rules, the shield placeholder protocol, and memory-recall keywords even after lossy compaction. `PreCompact` writes a session-scoped flag; the next `UserPromptSubmit` consumes the flag (one-shot) and prepends the cheatsheet text via `additionalContext`. ~400 tokens per compact. Phrased as informational, not directive.
  - Install also extends the managed CLAUDE.md section (`<!-- claude-secret-shield:* -->` markers, name preserved for upgrade idempotency) to cover all redmem tools — Shield, Image compressor, Autopilot, Memory — instead of Shield only.
  - 8 tests (`test_cheatsheet.py`) including two end-to-end stdin runs against the real dispatcher.
- **Image compressor** (`hooks/image_compressor.py`): transparently downscale large images before Claude reads them, cutting vision tokens (~66% on a typical phone screenshot) without altering the on-disk file.
  - Fires from `PreToolUse(Read)` via the dispatcher; returns `updatedInput` with a compressed cache path.
  - Thresholds: only rewrites images > 500 KB AND longest side > 1920 px. Smaller images pass through unchanged.
  - Uses macOS-native `sips` (no Python dependencies); fail-open on non-macOS or any tool error.
  - Cache: `/tmp/redmem-img-cache/<sha1>-<mtime>.<ext>` — mtime in filename ensures edits invalidate.
  - Three opt-out layers: `REDMEM_NO_IMAGE_COMPRESS=1` env (host-wide), `.redmem-no-compress` file (per-project), `.orig.` / `.nocompress.` filename marker (per-image).
  - **Automatic request-original flow**: after Claude reads a compressed image, a PostToolUse `additionalContext` tells it exactly how to get the uncompressed version if it needs pixel-level detail. Claude issues the sentinel bash command `redmem-original <path>`; a PreToolUse(Bash) hook intercepts it (the command is not a real program), writes a session-scoped flag, and denies. The next `Read <path>` in that session sees the flag and passes the original through uncompressed. No human renaming; the sentinel runs entirely in-hook.
  - 36 tests (`test_image_compressor.py`) covering opt-outs, thresholds, cache invalidation, sentinel-bash intercept, flag one-shot + session scoping, PostToolUse notice sidecar logic, and a real-`sips` integration test (skipped where unavailable).
- **Autopilot module** (`hooks/autopilot/`): overnight spec-driven loop that keeps Claude Code working unattended.
  - Three slash commands: `/autopilot [max_loop=150] <full-spec-path>`, `/autopilot-stop`, `/autopilot-status`.
  - Stop-hook re-injects a continuation message every turn until Claude emits `[[AUTOPILOT_DONE]]` or a halt condition trips (max_loop, 5-turn no-repo-change streak, 10h wall clock).
  - Graceful human takeover: typing any non-continuation message auto-disengages the loop (hook detects absence of the continuation marker and pauses state — no command needed).
  - **Preflight health check**: `/autopilot` refuses to arm on protected branches (main/master/trunk/develop/dev), refuses on a dirty working tree, and warns when not in a git worktree.
  - **Bash guard** (only active during autopilot): `PreToolUse(Bash)` denies `rm -rf`, `find -exec rm`, `git reset --hard`, `git checkout -f`, `git clean -fdx`, `git branch -D`, `git push --force`, `DROP TABLE`/`DATABASE`/`SCHEMA`/`INDEX`, and `TRUNCATE TABLE`. Claude is told why and picks a safer alternative.
  - **Artifacts under `.autopilot/`**: `TASKS.md`, `QUESTIONS.md`, `IMPROVE.md`, `DONE.md`, `HALTED.md`, auto-generated `README.md`. Plugin auto-registers `/.autopilot/` into `.git/info/exclude` so nothing leaks into git.
  - Fail-open: any hook error allows stop, preventing a plugin bug from trapping a session in an unstoppable loop.
  - `test_autopilot.py`: 58 tests (arg parsing, state round-trip, all stop-hook decision branches, 21 parameterized bash-guard samples, preflight refusal/warn cases, idempotent git-exclude register).
- **Guard module** (optional, opt-in via `./install.sh --with-guard`): agent isolation guard that denies concurrent non-isolated `Agent` tool calls targeting the same git repo, preventing parallel subagents from stomping on each other's uncommitted changes. Standalone hook (not routed through the dispatcher); fail-open on any internal error. Includes `.guard_bypass` one-shot override and 11 hermetic tests (`test_guard.py`).
- **Memory module** (Phase 0-2): persistent session archive for Claude Code
  - `hooks/memory/db.py`: SQLite FTS5 schema + connection management
  - `hooks/memory/transcript_parser.py`: Claude Code JSONL parser (verified append-only format, skips compact_boundary/isCompactSummary markers)
  - `hooks/memory/ingest.py`: incremental turn archival (line_number based dedup)
  - `hooks/memory/search.py`: FTS5 full-text search with query sanitization (handles FTS5 syntax chars in natural language)
  - `hooks/memory/summarize.py`: resume context builder (session_state > milestone > recent turns, token-budgeted)
  - `hooks/memory/session_state.py`: heuristic session state generation (Goal/Plan/Done/Blocked/Decisions) + task/plan event tracking
  - `hooks/redmem_dispatcher.py`: single entry point routing to shield or memory based on hook event
  - `test_memory.py`: 21 tests covering DB, FTS5, parser, ingest, search, resume, session state
- **Pluggable backend architecture**: ArchiveBackend + VectorBackend abstract interfaces; SQLite (default) and PostgreSQL (enterprise) implementations documented
- **Architecture document** (`docs/design/architecture.md`): full technical specification, 13 rounds of Codex adversarial review

### Fixed
- **The secret vault could destroy itself, silently.** A 235-entry encrypted `~/.claude/.redact-mapping.json` came back as 6 plaintext entries mid-session; restored from backup, it was down to 1 a few minutes later. No single bad line of code — three individually reasonable behaviours composing into a data-destroying one:
  1. The machine's `python3` began resolving to an interpreter without `cryptography` (a newer brew python pulled in as a pipx dependency had taken over the linked `python3`), so `FERNET` became `None`. Nothing announced this. An `alias python3=...` in the user's rc made it worse rather than better: aliases exist only in interactive shells, so every check run by hand said one interpreter while every hook, subprocess and CI step got the other.
  2. `load_mapping()` handed the encrypted bytes to `json.loads`, failed, and returned an **empty** mapping — "unreadable" and "absent" were the same value.
  3. `save_mapping()` opens with `O_TRUNC`. One redaction later the whole vault was replaced by the one or two entries that invocation happened to mint, in plaintext.
  Every placeholder already written into a file became permanently unresolvable. Reproduced deterministically: 50 encrypted entries → 2 plaintext ones from a single `Read` event, the only precondition being a crypto-less interpreter.
  The fix has three parts, and the middle one is the easy one to leave out: **never write over a mapping that could not be read**; **stop redacting for that invocation** (minting placeholders while unable to persist them writes markers nothing can ever restore — losing the shield once is recoverable, corrupting a file is not); and **record it**, because a vault that quietly stops working looks exactly like one that works. `test_vault_integrity.py` pins all three plus two controls, since every assertion about the failure path also passes for a shield that is simply switched off.
- **A zero-byte vault was still treated as a clean first run**, and two hooks saving at once could lose an entry. Both surfaced by Codex review of the fix above. A crash between `O_TRUNC` and the write leaves exactly a zero-byte file, which the new guard then read as "nothing here yet" and started over. Writes are now `mkstemp` → `fchmod 0600` → `fsync` → `os.replace` → directory `fsync`, so a committed mapping is never zero-byte or half-written. Separately — and pre-existing, not a regression — concurrent hook processes did load-mutate-save, so the last writer dropped the other's entry and left an unresolvable placeholder baked into a file: measured at **5 of 8 entries lost across 8 real concurrent processes**. `save_mapping` now re-reads and merges inside one exclusive critical section (sidecar `.lock`, since the commit is a rename), disk winning on conflict because a binding already on disk may be baked into files this process never saw. 7 tests (`test_vault_durability.py`); 6 fail against the pre-fix hook.
- **The mapping is never persisted in plaintext when encryption is unavailable** — the mirror image of the incident above, found by adversarial review. An existing encrypted vault was already caught (it will not decrypt), but on a **first** run there is nothing to fail at, so redaction proceeded and `save_mapping` took its plaintext branch, writing the user's real secrets unencrypted while the shield reported success. `FERNET is None` is now a degraded state for the whole invocation. Plaintext persistence, originally a migration convenience, is gone: the one thing a tool whose job is hiding secrets must never do is put them on disk in the clear while claiming to have hidden them.
- **Four routes that left `{{PLACEHOLDER}}` markers baked into files.** (a) A `Read` whose PostToolUse arrived under a different session id found no backup — backups are session-keyed — and left the file redacted forever; it now restores from the sibling session's backup, but only when that backup provably re-redacts to what is on disk, so a stale one is rejected rather than silently reverting work. (b) `Write` creating a new file and (c) `Edit` on a file that previously had no secrets both had no backup to restore from; both are reachable in production because the dispatcher returns the *first* response, so a guard's `ask` discards the shield's `updatedInput` and approving it writes the original, placeholder-bearing input. Both now fall back to mapping-based restore. (d) Fail-open hid all of the above: a detector now re-reads after any restore attempt and reports placeholders that are **still resolvable in the mapping** — a placeholder that survives a restore *and* has an entry is a defect by definition, while unresolvable ones are prose (this repo's own README documents one) and are never reported. Recorded twice, because the two records fail differently: a durable JSON line in `~/.claude/vault/restore-errors.log`, and a PostToolUse warning naming the file, which is what makes it findable at the moment the file is wrong and still fixable. 16 tests (`test_placeholder_bake_no_backup.py`).
- **The Bash PostToolUse restore net had a hole for relative paths.** That pass exists precisely for read-modify-write scripts, but both of its candidate-path regexes required a leading `/`, so the ordinary shape (`p = 'README.md'; open(p,'w')...`) produced no candidates and any placeholder written back stayed on disk. Found in this repository's own README, where a documentation example DSN had been replaced by a placeholder and was sitting in the worktree ready to commit. Relative paths now resolve against the event's `cwd`. Also fixed the cause: `test_deploy_config_guard_e2e.py` was driving the real dispatcher with the real `HOME` against `REPO/README.md` — a `Read` PreToolUse redacts its target on disk and relies on a matching PostToolUse the test never sent. Both tests moved to `tmp_path`, with a guard that raises if any payload path resolves inside the repository.
- **`install.sh` wrote the bare word `python3` into every hook command**, which is what made the vault incident inevitable rather than unlucky: hook processes do not source your shell rc, so the `python3` that resolves correctly when you type it resolves to whatever the spawn environment has. The installer now walks candidate interpreters, requires `import cryptography` to succeed, and writes that interpreter's **absolute** path; `REDMEM_PYTHON` overrides; it refuses to install if none qualifies, rather than installing a shield that reports success and protects nothing. Two consequences followed, one caught by the existing suite: entry de-duplication compared whole command strings, so a machine-specific path meant every re-install appended a duplicate; and `uninstall.sh` had the identical exact-match logic, so it would have uninstalled cleanly only on the machine that wrote the entries — leftovers being worse than a failed uninstall, since the entries stay, the hook files are gone, and every tool call then fails to spawn. Both now match on the script path, anchored on a real `.claude/` path segment so a stranger's `~/tools/hooks/redmem_dispatcher.py` is not ours to delete. An interpreter path containing a single quote is refused rather than escaped, because the command string is embedded in JSON parsed by `jq --argjson` and getting that subtly wrong writes a `settings.json` that does not parse. 11 tests (`test_install_interpreter.py`), run against the real installer in an isolated `HOME`. Converged over 3 Codex rounds.
- **`deploy_config_guard.py` was never installed.** The dispatcher imports it unconditionally; the import error is caught, so the install reported success and every hook kept working — the guard simply did not exist in any real installation, while its 64 unit tests went on passing against the copy in the repo. Found by running the *installed* dispatcher by hand and reading its stderr. The regression test does the same rather than asserting a file list: it installs into an isolated `HOME`, feeds the installed dispatcher a real event, and fails on `No module named` or `ImportError`. Asserting the list would only restate the list; running it is what catches the next one. `uninstall.sh` had the mirror gap, caught by its own test the moment install started creating the file.
- **`git_guard` deny hint** now gives the file-message workaround (`git commit -F /tmp/msg.txt`) for the case where the trigger substring appears inside a commit message, and names the correct env override.
- **`uninstall.sh` rewritten** to cover all current redmem files and hook events. The old uninstaller was a leftover from the `claude-secret-shield` era and didn't know about the dispatcher, the autopilot/memory/guard modules, the image compressor, the cheatsheet helper, the slash commands, or the `PreCompact` / `SessionStart` / `Stop` event entries — running it would have left an inconsistent half-install. New version: removes every file install.sh writes, strips redmem entries from all seven hook events (jq filter fixed — old version's `any(.; ...)` against an array silently matched nothing), strips the managed CLAUDE.md section, preserves user-authored content (custom hooks, theme, other settings, unrelated CLAUDE.md sections, `custom-patterns.py`, the memory vault). Adds `--purge` to wipe the vault + `/tmp/redmem-img-cache/` + per-session secret mappings. Verified: clean uninstall, custom-hook preservation, `--purge` wipes, and install→uninstall→install round-trip produces a byte-identical CLAUDE.md.
- **Write tool silent failure**: PreToolUse(Write) no longer causes data loss when PostToolUse falls back to backup restore. Content-based crash recovery (hash + placeholder detection) replaces flag-based approach. (Codex R5-R10, 6 rounds)
- **Crash recovery safety**: Write backups distinguished from Read backups; restore_pending_backups uses content comparison to detect completed writes
- **Placeholder regex**: crash recovery now matches pattern names containing digits (e.g. AWS_S3_ARN, DB2_URL) with `[A-Z0-9_]+`

### Changed
- **`CLAUDE.md`** added at the repo root: the interpreter trap, the dispatcher's first-wins ordering hazard (the shield runs first but is emitted last, so any guard that answers in between discards its `updatedInput`), the shield's data model, the fail-open/fail-closed rule, the hermetic-test rules, install/uninstall symmetry, and the Codex review recipe. Written after a week in which each of those was learned by breaking something.
- **Post-compact cheatsheet** now includes `git_guard` awareness, so a compacted session still knows which `git add` forms are denied and what the safe alternatives are.
- Renamed from claude-secret-shield to redmem (redact + memory)
- Repository: github.com/tokligence/redmem
- **Shield housekeeping moved from `.gitignore` to `.git/info/exclude`**: `.tmp_secrets.*` temp files are now registered in git's *local* exclude list at file-create time (previously appended to the user's shared `.gitignore` on first Read, which leaked into PRs and never fired if Claude didn't Read the file). Existing stray `.tmp_secrets.*` files in users' working trees can be safely deleted; the new behavior prevents recurrence.
- **PreToolUse and PostToolUse now route through the dispatcher** instead of calling shield directly, so the autopilot bash guard + image compressor + image notice can all share one gateway. Shield is still invoked as the first step inside the dispatcher (same semantics, one extra subprocess hop). `SHIELD_POST` direct entry removed; `DISPATCH_POST` covers the combined matcher `Read|Write|Edit|Bash|Todo*|Task*|Plan*`.
- **install.sh prefers local files over curl** when run from a checked-out repo (`SCRIPT_DIR/hooks/...` / `SCRIPT_DIR/commands/...`). Earlier versions always fetched from GitHub main, which prevented installing a WIP branch locally.
